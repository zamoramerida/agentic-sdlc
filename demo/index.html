A Complete Demo of AI-Assisted Development

This demo shows how GitHub Copilot and disciplined practices work together to deliver software safely and transparently.

Key principle: Agents assist, but authorized humans always review and approve.

1

Understand the Problem

What happens

Start with a clear GitHub Issue describing the problem, desired outcome, and acceptance criteria.

  • Identify the user problem and constraints
  • Inspect existing code and patterns
  • Separate facts from assumptions
  • Define observable acceptance criteria

Evidence

GitHub Issue with:

  • Problem statement
  • Desired outcome
  • Acceptance criteria (checkboxes)
  • Constraints and risks
2

Plan the Work

What happens

For non-trivial work, the agent records a bounded plan with scope, affected areas, dependencies, and verification strategy.

  • Identify affected areas and files
  • Plan verification and testing approach
  • Consider risks and failure modes
  • Get human agreement on material decisions

Evidence

Issue comment or linked artifact with:

  • Bounded scope
  • Affected components
  • Verification plan
  • Risk assessment
3

Implement the Solution

What happens

The agent writes code following project conventions in focused, coherent increments.

  • Work in small, reviewable commits
  • Follow repository patterns and style
  • Add tests alongside behavior changes
  • Keep unrelated changes separate

Evidence

Pull request with:

  • Clear commit messages
  • Focused, reviewable diff
  • Tests or explanation if not applicable
  • Link to originating issue
4

Verify the Change

What happens

Automated checks run on the pull request. Tests, linting, and build validation provide evidence before human review.

  • Run narrowest relevant checks first
  • Expand validation when risk warrants
  • Test negative and edge cases
  • Report exact checks run and results

Evidence

PR checks report:

  • Build success/failure
  • Test results with coverage
  • Linting and quality checks
  • Required checks must pass
5

Human Review & Approval

What happens

An authorized person reviews whether the change solves the problem with credible verification. Agents cannot approve their own work.

  • Verify problem is solved
  • Check scope is respected
  • Assess code quality and maintainability
  • Approve or request revisions

Evidence

GitHub PR review with:

  • Approval from authorized reviewer
  • Required checks passing
  • No unresolved conversations
  • Ready for merge
6

Ship & Learn

What happens

Only an authorized person or governed automation may merge or deploy. The change is released and outcomes are evaluated.

  • Merge approved PR to main
  • Automated deployment to GitHub Pages
  • Monitor deployment status
  • Evaluate outcomes against criteria

Evidence

Deployment shows:

  • Merge commit on main
  • Deployment workflow triggered
  • Public site updated
  • Rollback plan documented

Key Principles

🤝 Humans Accountable

Authorized humans review, merge, and deploy. Agents assist but never approve their own work.

📊 Evidence-Driven

Decisions are based on traceable verification, not confidence or generated explanations.

🔍 Fully Traceable

From issue to PR to deployment—every step is visible and linked for accountability.

⚠️ Risk-Aware

Scale verification, review, and deployment caution to match the change's complexity and risk.

See This Demo in Action

To experience the full agentic SDLC workflow:

  1. Open an issue on the agentic-sdlc repository
  2. Use Copilot to implement the issue and open a PR
  3. CI checks automatically validate the change
  4. Human review the PR and approve if it meets acceptance criteria
  5. Merge to main and watch automated deployment to GitHub Pages
  6. Verify traceability from issue → PR → deployment

Anti-Patterns to Avoid

  • ❌ Starting implementation from a vague prompt without clarifying the outcome
  • ❌ Accepting large, unexplained diffs because they were generated quickly
  • ❌ Skipping tests, diff review, or negative-case analysis
  • ❌ Fabricating test results or silently swallowing failures
  • ❌ Letting an agent bypass review, merge, or deploy without authorization
  • ❌ Treating more prompts, agents, or code as progress when it doesn't improve verified outcomes
